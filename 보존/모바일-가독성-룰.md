# 📱 모바일 가독성 룰 (앞으로 모든 작업의 기본)

> 깃허브 모바일 앱·모바일 브라우저에서 아내와 같이 보기 좋게.
> **앞으로 만드는 모든 마크다운 파일은 이 룰을 따른다.**

---

## 🎯 핵심 원칙

**1. 폭이 좁다 (모바일 ≈ 360~430px)**
**2. 한 화면에 한 항목**이 보일 정도로 압축
**3. 스캔 가능한 구조** — 이모지·굵은 글씨·구분선

---

## 1. 📊 표 사용 룰

### ❌ 절대 안 됨
- **4컬럼 이상 표** — 가로 스크롤 또는 글자 작아짐
- **셀 안 텍스트가 긴 표** — 한 셀에 30자+ 문장 ❌

### ✅ OK
- **2~3컬럼 표** — 모바일에서도 읽힘 (단, 셀 텍스트 짧게)
- **참조용 작은 표** — 환율 환산, 가격 비교, 시간표 등

### 🔄 큰 표 → 카드 단락으로 변환

❌ 변환 전:
```
| 이름 | 위치 | 시간 | 가격 | 5세 | 적합도 |
|---|---|---|---|---|---|
| 미케 비치 | 푸라마 10분 | 일출/일몰 | 무료 | ◎ | ★★★★★ |
```

✅ 변환 후:
```
**미케 비치** ★★★★★
🏖️ 세계 6대 해변, 다낭 얼굴
📍 푸라마 차 10분 · ⏰ 일출/일몰 · 💰 무료 · 👶 ◎
```

## 2. 🃏 카드 단락 형식

### 명소·식당 카드
```
### N. 이름 (영문) ⭐ 적합도
🏷️ 한 줄 정의

📍 위치 · ⏰ 시간 · 💰 가격
👶 5세 친화도 · ⏱️ 소요시간

**우리 가족 적합도**: ★★★★☆ — 이유

> "한국인 후기" — 출처

---
```

### 정보·역사 카드
```
**시대 / 항목명** — 핵심 한 줄
부연 설명 (2~3줄, 짧게)
```

---

## 3. 😀 이모지 사용 룰

각 카테고리에 **고정 이모지** 사용 (일관성):

**위치·이동**
- 📍 위치 / 🚐 이동 / ⏱️ 소요시간

**시간·일정**
- ⏰ 시간 / 🌅 일출 / 🌇 일몰 / 🌃 야간

**돈·예약**
- 💰 가격 / 🎟️ 티켓 / 📞 예약 / 📱 카톡

**가족·아이**
- 👶 5세 / 👧 9세 / 👨‍👩‍👧‍👦 가족

**평가**
- ⭐ 추천 / ★ 별점 / 🟢 권장 / 🟡 주의 / 🔴 비추 / ⛔ 금지
- ⚠️ 경고 / ✅ 확인 / ❌ 안 됨

**음식·카페**
- 🍴 식당 / 🍜 국수 / 🥖 빵 / 🍕 피자 / ☕ 카페 / 🥥 코코넛

**자연·랜드마크**
- 🏖️ 해변 / 🏔️ 산 / 🌊 바다 / 🛕 사찰 / ⛪ 성당 / 🏛️ 박물관 / 🎡 놀이공원

---

## 4. 🪓 단락 길이

- **한 단락 = 3~5줄 이내**
- 한 줄 = 한국어 30~40자 권장 (모바일 1줄 정도)
- 한 단락 다 읽고 다음으로 자연스럽게

---

## 5. ➖ 구분선 사용

**섹션 간 `---`**
명소 카드끼리, 시간대 블록끼리, 큰 주제 전환 시.

```
**카드 1**
...

---

**카드 2**
...
```

---

## 6. 🎨 강조 사용

### 굵은 글씨 (`**...**`)
- 명소·식당 이름
- 핵심 수치·가격
- 시간 (예: **17:00**)
- 결정 키워드 (예: **무료**, **절대 ❌**)

### 인용구 (`>`)
- 한국인 후기
- 중요 인용
- 경고·주의

```
> "푸라마 바로 앞 일출 명소" — 트립스토어 (2025)
```

### 코드 블록 (` ``` `)
- URL 묶음
- 카톡 문구
- 코드 예시

---

## 7. 📝 헤딩 사용

```
# H1 — 파일 제목 (1번만)
## H2 — 큰 섹션 (자연·해변 / 사찰 등)
### H3 — 개별 카드·항목 (1.1 미케 비치)
#### H4 — 카드 내 소항목 (적합도, 후기 등) — 거의 안 씀
```

H4 깊이까진 거의 가지 않음. **H3 + 굵은 글씨**로 충분.

---

## 8. 🔗 링크 처리

### 출처 URL
인용 끝에 짧은 라벨로:
```
> "..." — 트립스토어 (2025) [출처](https://...)
```

### 본문 링크
```
[자세한 카드 →](./1-자연·해변.md)
```

## 9. 🚫 모바일에서 깨지는 것들

- ❌ HTML 테이블 (마크다운 외)
- ❌ 옆 칸 비교가 필수인 큰 표
- ❌ 너무 깊은 중첩 리스트 (3 depth+)
- ❌ 한 줄에 50자+ (단, 코드 블록은 OK)
- ❌ ASCII 아트 (지도·다이어그램은 이미지로)

## 10. ✅ 작업 체크리스트

새 마크다운 파일 만들 때:

- [ ] 표가 4컬럼 이상이면 카드 단락으로
- [ ] 헤딩 레벨 일관 (H1 → H2 → H3)
- [ ] 각 항목에 적절한 이모지
- [ ] 섹션 간 `---` 구분선
- [ ] 핵심 정보는 굵은 글씨
- [ ] 출처 URL 짧은 라벨
- [ ] 한 단락 3~5줄
- [ ] 모바일 시뮬레이터 또는 실제 폰에서 확인
